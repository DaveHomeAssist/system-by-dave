Cause a screen tear, then fix it

Seven short steps on why a line rips across a screen and how frame sync and genlock stop it. Free, no sign-up. Motion is slowed down so you can see it.

1 / 7

  1. Step 1 of 7

    A screen paints one line at a time

    A display doesn't show a picture all at once. It draws it from the top down, line by line, then pauses briefly (the blanking interval) before starting the next pass. The bright line is where it's drawing right now.

  2. Step 2 of 7

    The new frame arrives during the pause

    The source (a computer, media server or camera) hands over a new frame for each pass. When that handover happens during the pause, every pass shows one whole frame. The green ticks below mark handovers that landed in the pause.

  3. Step 3 of 7

    Break it: swap frames mid-pass

    Now the source swaps frames whenever it's ready, even halfway down the screen. Everything above that point still shows the old frame and everything below shows the new one. The seam between them is a tear.

  4. Step 4 of 7

    Fix it: only swap during the pause

    Hold each new frame until the screen finishes its pass, then swap in the pause. On a computer that's vsync; on video gear it's frame sync or frame lock. Every pass is one whole frame again, so the tear is gone.

  5. Step 5 of 7

    Clocks that almost match make the tear crawl

    Two devices running on their own clocks never match exactly. 59.94 and 60 frames per second slip a whole frame about every 17 seconds, so the swap lands somewhere new on each pass and the tear wanders. It's sped up here so you can watch it move.

  6. Step 6 of 7

    On a show, lock everything to one reference

    In a rig, gear that supports it (cameras, switchers, media servers, LED processors) can lock to one reference signal, such as black burst or tri-level sync. That's genlock. Everything shares one clock and one frame boundary, so nothing drifts.

  7. Step 7 of 7

    Next time a line rips across a screen

    Check sync before you blame the cable: is the source syncing its output to the display (vsync, frame lock)? Do the frame rates match exactly (59.94 isn't 60)? Is everything that should be on reference actually locked to it?

The words, briefly

Scan-out
The display drawing each frame top to bottom, line by line.
Blanking interval
The short pause between passes. Swapping frames here never shows a seam.
Vsync, frame sync, frame lock
Making the source wait for that pause, or retiming its frames to the display, instead of swapping mid-pass.
Genlock and reference
Locking several devices to one shared timing signal (black burst or tri-level sync) so their frames start together.

This is a simplified model of a single display. Real gear differs in the details (some processors buffer or drop frames instead of tearing), but the cause and the fix are the same idea.
