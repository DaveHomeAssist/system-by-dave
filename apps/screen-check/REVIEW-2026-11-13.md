# Ten-area review: Screen Check 1.0.2

Scope: native `apps/screen-check`, after 1.0.1. No display mode, projector,
relay, playback or login-registration change is part of this review.

| Area | Result and change | Evidence boundary |
| --- | --- | --- |
| Verification correctness | Retained identity-before-timing and conservative unknown behavior. Added refresh-boundary and per-output failure tests. | Passing Mac configuration still does not prove downstream image delivery. |
| Architecture | Extracted `CheckModel`, environment and file/session operations from the UI entry point. The model accepts an injected session. | Kept native observation on the main thread; no new runtime framework. |
| Startup/reconnect | Capped event-burst postponement at six seconds. Added an OS-held single-instance lease and deduplicated requests to reopen the existing window. | Actual Studio login/reboot remains a hardware acceptance step. |
| Error handling | Check/reconnect clears obsolete action messages. Read failure, save warning and export failure remain separate. Previous readings are labeled during a pending check. | Retained reports on disk can be older; their timestamps remain authoritative. |
| Regression testing | Added boundary, non-regular-file, private-write, lock-contention, debounce and injected UI-model tests. | Source fixtures are not native accessibility or physical reconnect tests. |
| Performance | Measured core evaluation, native observation, profile reads and private writes separately. Retained event-driven operation and bounded work. | Measurements are a local snapshot, not a guarantee on every show Mac. |
| Security/privacy | Descriptor validation avoids path-check/open races and rejects FIFOs without waiting. Reports are owner-only before content is written and replace atomically. | Existing exported files are unchanged. Exported reports still contain device identifiers. |
| Accessibility | Explicit UNKNOWN label, primary-contrast status text, one complete accessible row, keyboard shortcuts and smaller minimum window. | VoiceOver spoken output and minimum-OS rendering require separate native acceptance. |
| Build/dependencies | Clean staged bundles, overlapping-output lock, source/toolchain manifest and extracted-package verification. CI tests removal of an obsolete resource. | Compile target is macOS 13; CI runs macOS 15. Signing alone is not notarization. |
| Documentation/DX | Added a compact troubleshooting card and signal-boundary diagram, maintainer map, upgrade and release-gate instructions. | Never derive the approved show profile automatically from a potentially faulty setup. |

## Reproduced before correction

- A failed `CheckModel.check()` left the previous `Fresh report saved.` message
  visible beside the new read error.
- `build.sh` retained a planted retired resource in its rebuilt app bundle.
- An ordinary atomic report write produced mode `0644` on the test Mac, exposing
  included device identifiers to other local accounts that could access its path.
- The original duplicate-process algorithm allows both starters to see the
  other and exit. The replacement uses kernel lock ownership rather than this
  check-then-act decision; lock contention and release are covered directly.

## Verification

`bash apps/screen-check/test.sh` runs 90 core/file/lifecycle cases and 11 injected
model transitions. No live profile is written by these tests. Six isolated
intentional mutations were rejected by the suite: accepting wrong output pixels,
widening refresh tolerance, making report files `0644`, removing the debounce
bound, retaining stale success feedback and bypassing instance locking.

The package gate extracts the actual ZIP, verifies its signature and arm64
identity, checks metadata/resources/LaunchAgent arguments, and runs its CLI with
an explicit missing profile to verify failure without falling back. Set
`REQUIRE_NOTARIZED=1` to additionally require a clean source revision, stapled
ticket and Gatekeeper acceptance. The gate does not claim a GUI or reboot test.

The forbidden-API scan in `test.sh` is a regression tripwire, not a security
proof. Source inspection confirms this version has no display-setting,
projector-control, shell-execution or network transport path in the application.
Distributed notifications carry only a local window-open request token.

## Performance and remaining acceptance

The pre-change fixture run measured 1,000 five-screen evaluations in 209 ms and
one cold native stable read in 172 ms on the local arm64 Mac. These different
operations must not be treated as comparable benchmarks. An optimized candidate
measured 1,000 evaluations in 181 ms, 100 profile reads in 7.2 ms, and 50 private
report writes in 19.6 ms. Ten native reads ranged from 0.59 to 115.5 ms, median
0.70 ms. This does not justify moving AppKit observation off the main thread or
adding continuous polling. Exact-package acceptance is recorded with the artifact.

Actual macOS 13 runtime, production Studio identities, five-output match,
FileVault/login/reboot, physical disconnect/reconnect, and real VoiceOver speech
remain separate acceptance lanes. Local development launch never substitutes
for Apple notarization or a Gatekeeper-approved downloaded installation.
