# Teach observable control skills

Start with the operator's actual difficulty and the consequence of a wrong action. Teach one decision or operation at a time. Match detail to the audience; do not require experienced operators to read a beginner introduction for each task.

## Define the lesson

1. Identify the equipment/model, the task, the likely confusion, and what evidence establishes the control's label, position, and function. Reuse component IDs. If exact placement is unknown, teach the distinction with an illustrative view and leave the physical locating step unverified.
2. State an observable outcome, such as finding the pan lock and distinguishing it from pan drag. Avoid objectives like 'understand the tripod' that cannot be assessed.
3. Specify the starting condition, short action, expected observation, and one meaningful wrong alternative. Use manufacturer procedures for model-specific sequences, limits, or calibration. Preserve any named coordination requirement. Do not invent clockwise directions, button hold durations, settings, or a universal plate-release sequence.
4. Provide the immediate operator instruction first; put mechanism, routing, evidence, and engineering detail behind an optional expansion. Do not hide a necessary precondition or stop point there.

Use [lesson design and assessment](references/lesson-design.md) for scoring and physical transfer. Adapt [the lesson template](assets/lesson-template.json) for an app, or use the same fields in a concise card.

## Implement practice

Offer a short demonstration, a guided attempt, then an independent attempt with labels/highlights removed when appropriate. Provide the same task through an accessible component list or descriptions; visual search alone is not the whole learning objective. Provide progressive hints and an explicit reveal action.

Track first-attempt choice, wrong selections, hints, reveals, completion, and optional elapsed time. A revealed answer is assisted completion, not independent success. A retry after a reveal remains assisted for that attempt. Reset assistance only on a genuinely new attempt; distinguish a fresh assessment from rehearsing the same answer.

Explain the consequence of an incorrect selection and let the learner recover. Do not reward random clicking or make speed the sole measure. Keep timing optional and avoid arbitrary pass thresholds without a task reason or baseline.

## Respect the physical task

For tripod lessons, distinguish movement locks, drag resistance, counterbalance, camera release, sliding-plate clamp, and any secondary catch. Only include mechanisms present on the fitted model. Teach camera removal with the supported assembly and the exact manufacturer's procedure; an unidentified plate supports an identification lesson, not executable release instructions.

For exposure/focus lessons, separate capture changes from display aids, ordinary focus from calibration, and local controls from remote control. Simulate changes explicitly; never imply that a trainer altered the actual rig.

Maintain distinct records for lesson completion, field check results, and equipment condition. Passing a simulation must not mark a camera ready. A field 'Pass' must correspond to an observed, defined test and include the rig/configuration, observer, and time.

## Verify usefulness

Check feedback, hint accounting, keyboard/touch operation, and selection alignment. Where feasible, observe an operator perform the same task on the actual rig and assess later retention. Report mistakes and assistance as well as time. Claim training effectiveness only from that evidence. Deliver the lesson and its untested physical-transfer scope without requiring field access to finish the instructional artifact.
