# Correction scope and closure

## Impact table

| Change | Dependents to inspect |
| --- | --- |
| Visible label or model identity | Catalog, photo labels, mesh groups, headings, alt text, search, deep links, manuals |
| Attached versus integrated part | Parent transform, clamp geometry, component ownership, highlight bounds, framing, operating notes |
| Hinge/pivot location or movement | Moving children, screen faces, controls, cables, hit tests, view presets, slider limits |
| Function or procedure | Operator instruction, expected result, caution/coordination, quizzes, troubleshooting |
| Installed patch | Endpoint IDs, direction, route layers, field checks, affected date/configuration |
| Evidence downgrade | Badges, sourced claims, learning prompts, release notes, any readiness implication |

Search source files and generated artifacts separately. Generated bundles may not preserve the original text; inspect the UI/data contract as needed. List only actual known destinations and relevant generated copies, not imagined mirrors.

## Closure evidence by surface

- Source: inspect the actual diff or current data/geometry.
- Export: open or parse the newly generated artifact and verify revision/content.
- Published page: read the deployed artifact and exercise the changed interaction when possible.
- Physical configuration: require a separate field observation; a corrected model cannot close this.

Keep the revision chain `old claim -> correction -> affected surfaces -> check evidence`. Record intentional legacy references as historical, not as remaining defects. Use a bounded set of searches and behavior checks; stop when the concrete change is sufficiently verified.

## Case-derived examples

A top-handle correction affects label, description, highlight, search, and quiz answer, but does not remove a separate real viewfinder elsewhere. A clamp-on focus demand requires two distinct components and their clamp; changing only the caption leaves the mechanical claim wrong. A move from a middle spreader to a ground spreader changes structure; it does not establish that the rig uses a wheeled dolly. Apply these as reasoning examples, not defaults for other equipment.
